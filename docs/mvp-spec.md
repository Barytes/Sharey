# Sharey MVP 可执行规格

状态：ready-for-agent。2026-10-11；依据产品定义、实施方案、领域词汇和 ADR-0001/0002。用户已授权 HTTP/CLI 测试接口、工程默认值、票据粒度和本地 tracker；本规格据此直接执行。

## Problem Statement

研究组成员需要让自己的 Agent 明确发布选定材料和研究记忆，让另一成员的 Agent 找到依据、获取完整 Skill 并接续研究。普通工作目录继续演进，已发布状态必须独立、只读且可追溯。

## Solution

交付一个 Python 3.12 包：自托管 FastAPI 服务、HTTP CLI、Sharey Skill、固定小型研究样例及确定性验收。每项目一个 bare Git 仓库；节点对应 commit，commit parents 精确表达研究派生；独立 ref 永久保留每次发布。客户端无需 Git，不建立共享仓库 clone。

## User Stories

1. 作为部署者，我可以指定持久目录、项目目标和共享凭证启动服务，让团队获得项目入口。
2. 作为成员，我可以使用项目凭证查询概览，让 Agent 找到研究目标、节点、关系、来源材料与 Skill。
3. 作为成员，我可以列出和读取所有已发布对象，让单节点获取不限制项目内访问。
4. 作为发布者，我可以通过带版本清单选择当前磁盘文件和记忆，让 dirty/untracked 内容也可发布。
5. 作为发布者，我可以只发布明确选取的文件，让私人文件留在本地。
6. 作为发布者，我可以继续使用原代码仓库，让发布不修改原文件、HEAD、index、配置或 remotes。
7. 作为读取者，我可以获取文件原始字节和节点归档，让文本、二进制与执行标记保持一致。
8. 作为发布者，我可以发布一份只读来源材料，让节点引用稳定依据。
9. 作为发布者，我可以分享完整 Skill 目录，让脚本、参考资料、模板和资源的相对路径保持完整。
10. 作为接收者，我可以在新目录实际运行下载的 Skill，让复用以产物验证。
11. 作为接续者，我可以发布单父分支和双父汇合，让概览与 Git 的研究 DAG 一致。
12. 作为接续者，我会收到缺失、跨项目、错误类型及重复父引用的明确错误，让无效发布不进入概览。
13. 作为成员，我可以在修改或删除本地材料后继续读取旧节点，让发布快照不可变。
14. 作为成员，我可以在网络结果不确定时用相同请求键重试，让一次发布只出现一次。
15. 作为成员，我可以与队友同时发布，让不同发布都可见，同键不同内容得到冲突。
16. 作为部署者，我可以停止、终止并重启服务，让已确认发布和幂等状态继续存在。
17. 作为成员，我在中断后重试发布，让未公开的半成品不可读、已经公开的发布不重复。
18. 作为成员，我可以指定新的下载位置，让原工作文件不会被覆盖。
19. 作为部署者，我可以限制包字节数、展开字节数与文件数量，让非法归档及超限请求明确失败。
20. 作为 Agent，我可以按 Sharey Skill 编译、引用和接续，让操作以可读取内容和真实执行结果为依据。

## Implementation Decisions

- 服务配置使用独立 JSON：项目标识、目标、token；配置不进入 Git 内容。启动时指定配置和持久目录。单 Uvicorn 进程，默认 loopback；令牌通过 Bearer header，CLI 从环境或全局参数读取。所有项目接口鉴权；错误不泄露项目内容。服务健康检查不含项目数据。
- HTTP 前缀 `/projects/{project}`；`GET overview`、`GET index`（Markdown 导航）、`GET nodes|sources|skills`、`GET nodes|sources|skills/{id}`、节点/Skill 的 `archive`、来源材料的 `file` 与节点的 `files/{path}`。发布为对应集合的 POST，`application/zip`，必须带 `Idempotency-Key`。成功 JSON，错误 JSON 与非零 CLI 退出码。
- CLI 提供 `overview`、`list`、`show`、`get`、`publish` 和 `serve`；对象单数用于 show/get/publish。发布节点使用 JSON 清单：`schema_version: 1`、title、summary、contributor、memory（相对清单的文件位置）、parents、sources、skills、files（source 到 path 的显式映射）。来源材料及 Skill 的标题、摘要与署名为参数。每次发布显式指定 `--key`；这是重试身份，不从文件修改时间推断。
- ZIP 中包含发布元数据，以及节点的研究记忆和选定文件、来源材料单文件或完整 Skill。文件路径是规范 POSIX 相对路径；拒绝绝对路径、空组件、点/父组件、反斜杠、控制字符、重复及文件/目录冲突。只接受普通文件与目录；拒绝符号链接和特殊文件。完整 Skill 必须有根 `SKILL.md`；保留空目录和可执行标记。默认包和展开内容各上限 16 MiB，条目上限 1000，可配置。
- 每项目、每对象类型、每请求键对应一个新建 ref，其目标是完整 commit；ref 同时是发布可见性和持久幂等记录，避免两个独立写入的崩溃间隙。节点 ID 是 commit OID；相同键和规范内容/文件/模式返回原结果，同键不同内容 409。单次原子创建 ref；构建 Git tree 不使用共享 index 或工作树。对象通过已发布 ref 授权读取，孤立 commit 不作为已发布对象。
- 节点父引用仅接受同项目已发布研究节点；来源和 Skill 引用按类型校验。parents 顺序保留；不进行自动内容合并。所有更新、修订另行发布；无覆盖或删除已发布对象接口。
- 快照以读入的实际字节和模式为准。CLI 可用 Git 时只执行只读命令，记录基线 commit、选定路径、相对基线的 clean/modified/untracked 状态及实际 SHA-256；Git 不可用仍可发布。出处不自动公开带凭证的 remote，不把源代码 ancestry 当研究父关系。
- 下载到显式新目标，保留原字节、相对目录和执行标记；已有目标（含链接）失败。归档先验证后在自己的临时位置展开并发布到新目标；失败清理暂存。CLI 不向厂商全局目录安装 Skill。
- 准备受控测试故障点：内容写入中、commit 完成/ref 创建前、ref 创建后/响应前。测试实际终止服务进程组并重启，证明进程故障恢复。部署文档区分该证据与断电/磁盘故障。

## Testing Decisions

- 主要公开接口为 HTTP 和 CLI 子进程；快速行为测试使用 FastAPI TestClient 加真实 Git，完整验收启动真实 TCP 服务。仓库尚无实现/测试，建立统一临时目录 fixture。
- 一次新增一个失败行为测试，然后最小实现到绿；保留 red/green 命令与结果。断言来自本契约与固定样例，不从被测函数推导。修改错误断言必须在工作记录说明原测试为何错误。
- 独立检查 Git commit parents 是 ADR 的存储契约；其余优先从公开读接口验证。并发、幂等、非法归档、权限、大小限制、原仓库不变、无 Git 客户端、重启和各阶段中断均须覆盖。
- 两个独立工作目录经真实 HTTP/CLI 完成源、Skill、根节点、获取和运行相对资源、两分支和双父汇合、旧快照和重启。独立 runner 检查固定输出、字节、关系和退出状态。
- 功能完成后尝试实际 Codex/Claude Code 新会话；记录 CLI/模型入口、尝试和产物。缺少登录或模型接入时记待验；两个 CLI 工作区仅为软件功能证据。

## Out of Scope

真实科研实验、GPU runner、相对普通共享的收益对照、Wiki/网页工作台、成员账号/角色、自动实验协调/评价、客户端 Git 同步、大型数据本体传输和云端 TLS 部署不作为本次功能完成条件。
